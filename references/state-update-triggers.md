# State Update Triggers

Write to `coaching_state.md` whenever:

- **kickoff** creates a new profile. Populates Profile, Career Goals, Company Context. Initializes empty Manager Background, Stakeholder Backgrounds, Performance Measures Tracker, Progress Snapshots, Artifact Library, Meeting Preps, Meeting Log, Feedback Stream. Writes initial Session Log row. On re-run (Mid-Role Update), preserves Artifact Library and Meeting Log; updates Profile and (with user confirmation) Role profile source.
- **ingest-manager** parses the LinkedIn PDF and writes Manager Background (career arc, prior roles) at `Confidence: Medium`. User-confirmed gap answers upgrade individual fields to `Confidence: High`. Sets `Last enriched: [date]`.
- **ingest-stakeholder** appends a row to Stakeholder Backgrounds and creates a corresponding Stakeholder Details block. Auto-assigns `K###`.
- **ingest-leveling** parses the leveling doc and appends rows to Performance Measures Tracker. Assigns `M###`. On re-ingest, diffs against existing rows and preserves history (deprecated rows get `(deprecated [date])` suffix, keep Supporting Artifact IDs).
- **log-company-goals** refreshes Company Context (mission, OKRs, priorities, source, last refreshed) and recomputes Priority Weight on all Performance Measures rows per the rules in `rubric-performance.md`. Appends a Session Log row.
- **log-artifact** writes a new row to Artifact Library and a Details block. Assigns `A###`. Updates linked Performance Measures' `Supporting Artifact IDs`. If this artifact pushes a measure's Evidence Strength to Moderate+ for the first time, `Current Maturity` may bump from `Emerging` to `Meeting` — surface the recommendation to the user before writing. Appends a Session Log row.
- **prep-1-1** writes a new row to Meeting Preps with `Status: Scheduled`, assigns `MTG###`, writes per-participant Participant Profile Snapshots into the Details block. Also writes the agenda, anticipated questions (grouped by participant), and questions-to-ask (grouped by participant). Appends a Session Log row.
- **prep-stakeholder** same as `/prep-1-1` but seeds the roster from the positional stakeholder arguments. If `--with-manager` or `--with-skip` flags are supplied, appends `MGR` or `SKIP` to the Participant IDs list. If a new stakeholder is inline-created during resolution, also appends a row to Stakeholder Backgrounds and a corresponding Stakeholder Details block.
- **log-1-1** writes a Meeting Log row (fka 1:1 Log). Prep-aware: if a matching Meeting Preps row (`Status: Scheduled`, `MGR` in Participant IDs, within 14-day window) exists and the user chooses `yes`, flips that row's `Status: Done`, appends debrief notes to its Details block, writes per-participant Relationship Drift Flags, links Meeting Log row ID. If the row contains explicit feedback, also writes a corresponding Feedback Stream row (de-duped by Date+Source+Verbatim). If the user mentions a manager priority or signal that updates Manager Background, write that too — ask before overwriting existing values. For `K###` participants in the room, same updates land in Stakeholder Backgrounds (Priorities, Open Gaps, Last Interaction, Relationship Last Reviewed). Updates linked measures' `Last Reviewed`.
- **log-stakeholder-meeting** writes a Meeting Log row with `Type: 1-1` or `group`. Same prep-match + per-participant drift logic as `/log-1-1`, but match rule is "Participant IDs contains the resolved `K###`." Routes per-participant updates to Stakeholder Backgrounds (and Manager Background if `MGR` was in the room). Writes Feedback Stream rows per participant with explicit feedback.
- **log-feedback** writes a Feedback Stream row. Source is resolved to a hard FK where possible (`MGR` or `K###`) via the attribution flow in `references/commands/log-feedback.md`. If `K###` is the source, also updates that stakeholder's `Last Interaction = today`. If source is `MGR` or `K###` and sentiment is Critical, adds a Coaching Note nudging the user to raise it at the next 1:1 or stakeholder meeting (does not auto-update Priorities / Open Gaps — those updates require the two-sided signal captured in `/log-1-1` or `/log-stakeholder-meeting`). If the feedback is Critical and linked to a High-weighted measure, surface the feedback floor trigger (see `rubric-performance.md`) for the next `/review-progress` call.
- **review-measures** walks the Performance Measures Tracker. May update `Current Maturity`, `Trend`, and `Last Reviewed` on each row. Does NOT write a Progress Snapshot (that's `/review-progress`).
- **review-progress** appends a new Progress Snapshot row with Momentum Score + Trajectory Call. Updates `Trend` on every measure. Shows the formula inputs in the response. Appends a Session Log row.
- **export-artifacts** writes the external file at `Profile.Interview-coach export path`. Appends a Session Log row with `Exported N artifacts to <path>`. Does NOT modify Artifact Library.
- **export-state** writes a bundle to a user-supplied path. Does NOT modify `coaching_state.md`. Appends a Session Log row.
- **import-state** overwrites `coaching_state.md` with the bundle contents AFTER explicit user confirmation. Appends a Session Log row referencing the import source.
- **daily** (pre or debrief) appends an entry under today's date header in Rhythms. Any capture routed inline (artifact, feedback, commitment) writes through its destination command's own trigger rules above, only after the user accepts it; the resulting IDs go on the entry's `Captures:` line. Debrief status flips write through `/commitment`'s flip rules (including any accepted Trust Log proposal). Appends a Session Log row.
- **weekly** (pre or debrief) same as `daily` for the Rhythms entry and inline captures. Debrief also runs `/review-progress` (Progress Snapshot + measure Trends per that trigger) and may launch `/vibe-check` inline during the trust review pass. Appends one Session Log row covering the whole run — the embedded `/review-progress` does not add its own.
- **status** reads state and renders the session-start summary; does not write except for appending a Session Log row for the status call itself (optional — skip if the user just opened the session without running any command).
- **Any session where the user reveals coaching-relevant personal context** (working-style preferences, review-cycle anxiety, scheduling constraints, how they handle feedback) — add to Coaching Notes.

## Mid-session saves

Write silently after any major workflow completes — not just at session end. If a long session is interrupted, no work should be lost. Only confirm saves at session end: "Session state saved. I'll pick up where we left off next time."

## Session Log cadence

Every command above that modifies state adds one row to Session Log. Keep the Key Outcomes column tight — one line.
